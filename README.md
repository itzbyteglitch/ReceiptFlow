AI-powered receipt and invoice extraction with a privacy-first dashboard.

ReceiptFlow sends receipt images to the backend for AI extraction and stores only the resulting structured data. Original images are processed in memory and are never stored as permanent receipt files or shown in the dashboard.

## Architecture

- **Frontend:** React + Vite + TypeScript, deployable to Cloudflare Pages
- **Backend:** Cloudflare Workers + TypeScript
- **AI:** OpenRouter using `dots-studio/dots-3-note-preview:free` with deterministic request settings and a strict JSON schema.
- **Database:** Cloudflare D1
- **Validation:** Zod
- **Charts:** Recharts

The Worker requests JSON-schema output and validates the returned object with Zod. The model and extraction settings are configured in the Worker.

## Data flow

1. User uploads a receipt from the Pages frontend.
2. The frontend sends the image as multipart form data to the Cloudflare Worker.
3. The Worker reads the image in memory and sends it to OpenRouter as a base64 data URL.
4. OpenRouter is instructed to return only the ReceiptFlow JSON schema.
5. Zod validates the returned object.
6. Only the structured receipt data is stored in D1.
7. The original image is not stored in R2, is never exposed to the frontend, and is not retained as a receipt file by ReceiptFlow.
8. The dashboard reads receipt data from D1.

## Required Cloudflare resources

Create:

- one D1 database
- one Worker
- one Cloudflare Pages project for `frontend/`

Then set the Worker secret:

```bash
npx wrangler secret put OPENROUTER_API_KEY
```

The API key is never shipped to the browser.

## Local development

### Worker

```bash
cd worker
npm install
npm run dev
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Set `VITE_API_URL` to the Worker URL when the frontend and Worker are hosted separately.

## D1 setup

```bash
cd worker
npx wrangler d1 create receiptflow-db
```

Put the returned database ID into `wrangler.toml`, then:

```bash
npx wrangler d1 migrations apply receiptflow-db --local
npx wrangler d1 migrations apply receiptflow-db --remote
```

## Receipt schema

Missing information is represented as `"unspecified"`. The model is explicitly instructed never to fabricate facts.

The schema supports both formal invoices and thermal retail receipts, including merchant/customer information, invoice numbers, shopping date/time, line items, taxes, discounts, payment information, notes, tags, confidence, and extraction warnings.

## Important privacy behavior

- Original receipt images are processed in memory only.
- Original images are not rendered in the frontend.
- No receipt image URL or R2 object is stored in D1.
- Users can delete receipt records from the dashboard.
- Spending analytics use the **shopping date**, not upload date.
- `uploaded_at` is generated by the backend.
