# ReceiptFlow

AI-powered receipt and invoice extraction with a privacy-first dashboard.

ReceiptFlow turns temporary receipt images into validated structured financial data. Original images are kept only for processing and are never shown in the dashboard.

## Architecture

- **Frontend:** React + Vite + TypeScript, deployable to Cloudflare Pages
- **Backend:** Cloudflare Workers + TypeScript
- **AI:** OpenRouter vision model. The default is `openrouter/free`, which currently routes to free models capable of the requested image/structured-output features.
- **Database:** Cloudflare D1
- **Temporary storage:** Cloudflare R2
- **Validation:** Zod
- **Charts:** Recharts

OpenRouter's free router can select free models that support image understanding and structured outputs, making it a good default for this prototype.

## Data flow

1. User uploads a receipt from the Pages frontend.
2. The Worker stores the image temporarily in R2.
3. The Worker sends the image to OpenRouter as a base64 data URL.
4. OpenRouter returns the ReceiptFlow JSON schema.
5. Zod validates the response and backend checks totals.
6. Structured data is stored in D1.
7. The original image is never displayed and is deleted from temporary storage within the configured 24-hour retention window.
8. The dashboard uses only D1 data.

## Required Cloudflare resources

Create:

- one D1 database
- one R2 bucket
- one Worker
- one Cloudflare Pages project for `frontend/`

Then set the Worker secret:

```bash
npx wrangler secret put OPENROUTER_API_KEY
```

The API key is never shipped to the browser.

## Local development

### Worker

```bash
cd worker
npm install
npm run dev
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Set `VITE_API_URL` to the Worker URL when the frontend and Worker are hosted separately.

## D1 setup

```bash
cd worker
npx wrangler d1 create receiptflow-db
```

Put the returned database ID into `wrangler.toml`, then:

```bash
npx wrangler d1 migrations apply receiptflow-db --local
npx wrangler d1 migrations apply receiptflow-db --remote
```

## R2 setup

```bash
npx wrangler r2 bucket create receiptflow-temp
```

Configure the bucket's lifecycle policy to delete objects under `temporary-receipts/` after 1 day. The application never exposes these objects to the frontend.

## Receipt schema

Missing information is represented as `"unspecified"`. The model is explicitly instructed never to fabricate facts.

The schema supports both formal invoices and thermal retail receipts, including merchant/customer information, invoice numbers, shopping date/time, line items, taxes, discounts, payment information, notes, tags, confidence, and extraction warnings.

## Important privacy behavior

- Original receipt images are temporary.
- Original images are not rendered in the frontend.
- No permanent image URL is stored in D1.
- Users can delete receipt records from the dashboard.
- Spending analytics use the **shopping date**, not upload date.
- `uploaded_at` is generated by the backend.
